## iOS Dev Weekly — Issue #18

### Opening

Package boundaries are quietly becoming the most dangerous surface in SwiftUI apps. As teams move screens into Swift Packages and centralize navigation with NavigationStack, encoded route values—simple Codable payloads—are the thing that trips you up at 2am when a subset of devices starts crashing. This week: practical ways to make navigation a value contract, not a fragile binary blur between host and package.

---

### This Week's Big Story

**NavigationStack Integration in Modular Swift Packages**

Converting a package that exported SwiftUI screens into a NavigationStack-driven host can expose a class of runtime mismatch: encoded route values crossing package boundaries may be decoded differently by host and package, producing crashes for some users and surfacing after rollout. Focus on enforcing a value-based navigation contract: small, versioned route types decoded where the host owns the path, decoder fallbacks, and explicit router interfaces. These practices reduce surprise crashes and make staged migrations possible without ripping up your release plan.

### Swift Snippet of the Week

```swift
public struct Route: Codable, Hashable {
  public var screen: String
  public var version: Int
  public init(screen: String, version: Int = 1) {
    self.screen = screen
    self.version = version
  }
}
```

This small, versioned Codable type encodes the engineering judgment: treat navigation targets as immutable value contracts so you can evolve payloads safely and perform compatibility checks where the host controls decoding.
