## iOS Dev Weekly — Issue #24

### Opening

Macros in Swift are moving from novelty to operational choice for teams adopting SwiftUI at scale, and that's exposing a silent risk: code generation can change where and when state is created and retained. If you treat macros as a pure developer ergonomics win, you will miss their impact on lifetime, re-renders, and allocations under load. This week's piece focuses on practical guards you can add when you introduce macros to a production codebase.

### Swift Snippet of the Week

```swift
import SwiftUI
import Combine

final class CounterModel: ObservableObject {
    @Published var count: Int = 0
    func increment() { count += 1 }
}

struct CounterView: View {
    @StateObject private var model = CounterModel()
    var body: some View {
        VStack {
            Text("Count: \(model.count)")
            Button("Inc") { model.increment() }
        }
    }
}
```

This pattern matters because it encodes clear ownership and lifecycle intent for stateful views — something you must preserve (or explicitly change) when introducing macros that synthesize similar types.
