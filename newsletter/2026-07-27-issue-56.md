### Opening

We’re all shipping “AI features,” but the part that keeps biting teams isn’t models—it’s surface area. Apple Intelligence leans on App Intents and entities, and if those contracts are fuzzy or UI‑coupled, the system will find the seams first. This is the week to harden your headless paths.

### This Week's Big Story

**Designing App Intents for Apple Intelligence on iOS**

Siri and system search won’t babysit your UI; they’ll call straight into your domain, often off the main actor, and expect deterministic results. If your “background” path reaches for view models, singletons bound to scenes, or unbounded queries, you’ll see timeouts, nondeterminism, and broken shortcuts that users can’t diagnose. The article gets specific about modeling entities, scoping parameters, and isolating state so Apple Intelligence can reliably compose your app like a backend.

### Swift Snippet of the Week

```swift
import AppIntents

struct AddTaskIntent: AppIntent {
    static var title: LocalizedStringResource = "Add Task"
    static var description = IntentDescription("Create a new task in a specified list.")

    @Parameter(title: "Title")
    var taskTitle: String

    @Parameter(title: "List", default: nil)
    var list: TaskListEntity?

    func perform() async throws -> some IntentResult & ProvidesDialog {
        let created = try await TaskService.shared.createTask(title: taskTitle, listID: list?.id)
        return .result(dialog: "Added “\(created.title)”")
    }
}
```
