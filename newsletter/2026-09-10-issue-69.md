### This Week's Big Story

**AsyncSequence Patterns for Real-Time SwiftUI Views**

SwiftUI is fine with “fast enough,” but it falls apart with bursty, unordered, or long-lived inputs unless you own buffering, cancellation, and isolation. The core move is to treat each live source as an AsyncSequence boundary you can reason about and test, not as a delegate call spraying mutations across the app. If you’ve ever shipped a screen that only recovers after a full relaunch, this is the mental model that prevents it.

### Swift Snippet of the Week

```swift
import SwiftUI
import Observation

struct TickerEvent: Identifiable, Sendable { let id = UUID(); let value: Int; let time: Date }

actor TickerSource {
    private var continuation: AsyncStream<TickerEvent>.Continuation?
    private var pump: Task<Void, Never>?
    let id = UUID()
    func stream(buffer: Int = 64) -> AsyncStream<TickerEvent> {
        AsyncStream(bufferingPolicy: .bufferingOldest(buffer)) { cont in
            continuation = cont
            cont.onTermination = { [weak self] _ in Task { await self?.stop() } }
        }
    }
    func startDemo() {
        pump?.cancel()
        pump = Task {
            var n = 0
            while !Task.isCancelled {
                for _ in 0..<Int.random(in: 1...6) {
                    n += 1; continuation?.yield(.init(value: n, time: .now))
                }
                try? await Task.sleep(for: .milliseconds(Int.random(in: 60...220)))
            }
```
