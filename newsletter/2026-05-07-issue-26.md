## iOS Dev Weekly — Issue #26

### Opening

Sequential motion in SwiftUI starts simple and gets brittle fast: scattered withAnimation calls, shared observable flags, and concurrent state updates produce flicker, multi-render spikes, and views left mid-animation. This week I want to show a pragmatic way to own motion sequencing so your UI behaves under load and cancellation — not just on the simulator.

---

### This Week's Big Story

**PhaseAnimator Techniques for Smoother SwiftUI Animations**

Phase-based coordination centralizes sequencing and interruption handling so animations don't fight each other. It reduces jitter under CPU pressure by making ordering explicit and measurable. If your screens depend on multi-step choreography, you'll want to think in phases, not isolated withAnimation calls.

### Swift Snippet of the Week

```swift
import SwiftUI
import Observation

enum MotionPhase: Int {
    case idle, entrance, emphasis, settle
}

@MainActor @Observable
final class PhaseAnimator {
    var currentPhase: MotionPhase = .idle
    private var runningTask: Task<Void, Never>?

    func runSequence() {
        runningTask?.cancel()
        runningTask = Task { [weak self] in
            guard let self else { return }
            await transition(.entrance, duration: 0.25)
            try? await Task.sleep(nanoseconds: 200_000_000)
            if Task.isCancelled { return }
            await transition(.emphasis, duration: 0.35)
            try? await Task.sleep(nanoseconds: 300_000_000)
            if Task.isCancelled { return }
            await transition(.settle, duration: 0.28)
            try? await Task.sleep(nanoseconds: 150_000_000)
            if Task.isCancelled { return }
// … (truncated for newsletter)
```

This pattern encodes ownership, interruption, and explicit timing — the sort of engineering trade-offs you want in your mental toolkit when UI choreography must be predictable.
